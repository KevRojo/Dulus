- August 28, 2026 (**v3.12.1**): **🚨 A failed run was still reporting success — and answering with your gold memory.** Caught by actually running yesterday's wheel against a provider that wasn't logged in. `--output json` split the channels correctly and the frames were right, but the *verdict* was wrong: `dulus --print --output json -- "di hola"` exited **0** and emitted a `text` frame whose contents were the dump of your golden memory. Two defects stacked. **First, the failure was invisible.** Almost no provider failure raises — the provider ends the turn with `error=True`, the agent loop rolls the turn's messages back and breaks, and there is no exception, no `TurnDone` and no new assistant message left behind. Both of 3.12.0's guards were watching for things that never happened. The agent loop now records *why* the turn it just ran failed, and `err()` records the last thing reported to you — at the shared layer, so it catches every module instead of just the CLI. **Second, the answer wasn't scoped to the turn.** Gold memories are injected as `role: "assistant"` at boot, so reading "the last assistant message" after a rolled-back turn returned a memory file and called it the reply. The answer now comes from the loop's own record of the turn (which also survives mid-run auto-compaction), bounded by the message count from before the turn started. And the floor under all of it: **a turn that produced no answer is always `error` + exit 1**, whatever the cause — including causes we haven't thought of yet, and including a turn that streams half a sentence and then dies. Also fixed: `--version` and `--help` now answer on stdout in every mode instead of vanishing into stderr under `--output json`. If you're embedding Dulus, upgrade past 3.12.0 — this is the difference between "the run failed" and "the run succeeded and said something strange". `pip install --upgrade dulus`. 🦅🇩🇴

- August 28, 2026 (**v3.12.0**): **🔌 Dulus is now embeddable — `--output json`.** Dulus already ran fine as a one-shot (`dulus -p "…"`), but it was impossible to *drive* from another program. Three things were in the way, and all three are fixed. **(1) Channels.** Every human-facing byte — the boot banner, spinners, tool status lines, warnings, Rich's cursor repaints — went to stdout, mixed in with the answer, so a parent process parsing stdout got `🦅 Dulus — [FREE] …` as line one and gave up. `--output json` now reserves stdout for a clean **JSONL protocol stream** and sends *everything else* to stderr — one swap, before the first print can fire. **(2) Frames.** stdout carries four frame types: `step_start` (with the session id), `text` (the assistant's answer), `step_finish` (input/output/cache tokens plus estimated cost, accounted exactly like `/cost` so the two can't disagree), and `error`. We deliberately speak the **OpenCode event-stream dialect** instead of inventing our own, so a tool that already parses that format needs **zero new code** to run Dulus. **(3) Exit codes.** A one-shot run used to exit **0 no matter what** — an expired key, a quota wall, a missing credential, all indistinguishable from success. Now every failure path emits an `error` frame *and* exits non-zero (`130` on Ctrl+C), so a parent can tell a finished run from a dead one. Protocol mode also refuses to hand your prompt to an already-running Dulus over IPC — that would answer in the *other* process's directory and emit no frames at all. Try it: `dulus -p --accept-all --output json -- "explain this repo"`. If the first line of stdout isn't a JSON object, that's a bug — report it. `pip install --upgrade dulus`. 🦅🇩🇴

- July 29, 2026 (**v3.10.55**): **🧊 Stopped quietly burning the prompt cache on every tool turn.** This one hid in plain sight.
